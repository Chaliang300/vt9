# 切换动画建议

2026-11-01。这份是**建议**，还没有落到代码里。对象是当前的 VT9Status 主界面：
窗口固定 800×614、`WindowStyle=None`、`AllowsTransparency=false`、背景走 DWM 原生 Acrylic，
页面是三个手算坐标的 `Canvas`，全部靠 `Visibility` 切换。

## 一、这个程序里"切换"出现在哪四处

| 场景 | 现状 | 值不值得做动画 |
| --- | --- | --- |
| 左导航切页（概况 / DPI / 参数） | `Visibility` 同帧硬切，`SelectPage()` | **值得**，最明显的一处 |
| 外观设置浮层开合 | 打开已经是 `PopupAnimation.Fade`；关闭是硬消失 | 打开够用，关闭可选 |
| 快捷切换档位（点顶部数字） | 高亮、大数字、提示同帧硬跳；写入要等约 1s 回读 | **值得**，能把感知延迟压到 0 |
| 托盘菜单 | WinForms 原生绘制 | 不建议动 |

## 二、建议（按性价比）

### 1. 切页：淡入 + 上移 6px，160ms，EaseOut —— 不做交叉淡出

- 给三个 `Canvas` 各挂一个 `TranslateTransform`；切换时只动**新页**的 `Opacity 0→1` 与 `Y 6→0`，
  旧页立即 `Collapsed`。
- 参数：**160ms**、`QuadraticEase(EaseOut)`、位移 **6px**。
- 为什么不做交叉淡出：两页的卡片占同一批坐标，重叠的那一百毫秒会看到两层半透明卡片糊在一起；
  先撤旧页、再淡入新页最干净。
- 只动 `Opacity` 与 `RenderTransform`。这套界面是手算坐标（卡片 x=96/412、页脚 y=560），
  动 `Canvas.Left`/`Width`/`Height` 会牵动测量、描边和点击区，而且每帧重新布局；
  `RenderTransform` 只走合成器，零布局。

### 2. 重复切页要先"落定"

连点导航时上一段动画还在跑，`From/To` 会叠加（表现为忽快忽慢或闪一下）。每次开始前
`BeginAnimation(OpacityProperty, null)`、`BeginAnimation(TranslateTransform.YProperty, null)`
复位再重开。

### 3. 切档：把"等待"变成"反馈"

现状已经是：点一下 → 高亮与文案立刻切过去（`Invalidate()`）→ 约 1s 后回读落定文案。
界面本身不卡，缺的只是**读数变化的视觉连接**。

- 做法：`draftActive` 变化时给 DPI 页那个大数字一个 **180ms 的 `0.35 → 1` 呼吸**。
- 只在"值或活动档真的变了"时触发一次；不要每个刷新周期都呼吸。
- 拖动滑块时**不要**呼吸（大数字跟着滑块走，逐帧淡入淡出会抖）。
- 可选：把"正在切换到第 N 档…"保持到回读结束（现在就是这样），并让 chip 的靛蓝实底
  用 120ms 淡入而不是同帧硬跳（需要给每个 chip 单独的、未冻结的画刷再动 `Color`，
  共享画刷不能动，否则整页一起变）。

### 4. 打开系统开关就听系统的话

- `SystemParameters.ClientAreaAnimation == false`（设置 → 辅助功能 → 视觉效果 →
  "在 Windows 中显示动画"关掉）时**直接跳过动画**、一步到位。
- `SystemParameters.HighContrast` 同理（背景逻辑里已经在尊重它）。
- 这是"和系统风格统一"的一部分，也是无障碍要求，别硬播。

### 5. 时长与运动词汇要和现有设计一致

- 这个程序已有的瞬时反馈是 **400ms** 的托盘图标闪烁一次（`flashTimer`），动画建议统一在
  **120–200ms**，最长不超过 250ms。
- 只用"淡入 + 最多 6–8px 位移"；不要缩放、不要回弹、不要弹簧、不要透明度过冲。
  这套界面的气质是克制——动画只用来"接住"状态变化，不用来表达情绪。
- 缓动统一用 EaseOut（进场快、收尾慢）；不要用 `BackEase`/`BounceEase`。

### 6. 这几件事不要做

- **不要给窗口本体做 Opacity / Scale 动画。** 窗口是 DWM 合成的原生 Acrylic
  （`DwmSetWindowAttribute(hwnd, 38, …)`），而且 `ApplyBackdrop()` 里特意做了 250ms 的
  "无材质 → Acrylic"两帧过渡来避开黑闪。动窗口透明度会把渲染推回分层窗口路径，
  容易掉材质或闪一帧。
- **不要用 `CacheMode = BitmapCache`。** 这界面全是 12–17px 小字，位图缓存会糊字，
  首帧还更慢（缓存本身要一次完整渲染）。
- **不要做整页横向滑动。** 800×614 固定窗口要做横向滑动就得给内容套裁切容器，
  改动面大、收益低。

## 三、实现骨架（可直接用）

```csharp
// 切页：新页 160ms 淡入 + 上移 6px；旧页立即隐藏（不做交叉淡出，两层卡片会糊）。
// 只动 Opacity 与 RenderTransform：这套界面是手算坐标，动布局属性会牵动测量与描边。
private void AnimatePageIn(Canvas page)
{
    if (page == null || !IsVisible) return;                 // 构建期与后台不播
    if (!SystemParameters.ClientAreaAnimation) return;      // 系统关了动画就一步到位
    TranslateTransform slide = page.RenderTransform as TranslateTransform;
    if (slide == null) { slide = new TranslateTransform(); page.RenderTransform = slide; }
    page.BeginAnimation(UIElement.OpacityProperty, null);   // 连点导航时先落定上一段
    slide.BeginAnimation(TranslateTransform.YProperty, null);
    Duration span = new Duration(TimeSpan.FromMilliseconds(160));
    IEasingFunction ease = new QuadraticEase { EasingMode = EasingMode.EaseOut };
    page.BeginAnimation(UIElement.OpacityProperty, new DoubleAnimation(0, 1, span) { EasingFunction = ease });
    slide.BeginAnimation(TranslateTransform.YProperty, new DoubleAnimation(6, 0, span) { EasingFunction = ease });
}
```

调用点：`SelectPage()` 里设完三个 `Visibility` 之后调
`AnimatePageIn(选中的那一页)`。`BuildSurface()` 里那次初始 `SelectPage` 因 `IsVisible == false`
天然不播（窗口还没显示），所以启动时不会有"内容先淡一下"的闪烁。

切档呼吸同理：一个 `DoubleAnimation(0.35, 1, 180ms)` 打在 `dpiValueText` 的 `Opacity` 上，
触发条件是"活动档变了"，用一个 `lastAnimatedActive` 字段去重。

## 四、怎么证明它真的在跑

- "丝滑"是时间维度上的东西，截图看不出来。建议在动画的 `Completed` 回调里 `Program.Log` 一条
  （带毫秒差），跑 `--ui-preview` 时日志就能证明动画确实播了、实际时长是多少。
- 也可以用像素探针在动画中途验证：本轮验证页脚卡片底用的就是
  `System.Drawing.Bitmap.GetPixel`（截图 1000×768 = 逻辑 800×614 × 1.25）。
  想让截图停在动画中段，可以在预览路径里"截图前 80ms 触发一次切页"，
  那一张的不透明度应当约为一半。
- 最终观感还是你自己点两下最准。

## 五、落地顺序（如果要做）

1. 切页淡入（第 1、2 条）——约 20 行，只碰 `MainForm.Layout.cs`，不动任何坐标。
2. 切档呼吸（第 3 条）——约 15 行，碰 `MainForm.Layout.cs` 的两处刷新。
3. 系统开关（第 4 条）已经在第 1 条的骨架里。
4. 关闭浮层的淡出（第 2 个场景）——性价比最低，建议先不做。
