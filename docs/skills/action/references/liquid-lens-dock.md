# 透镜式纵向 Dock：一个 SVG 实现的设计分析

对象：用户给的 `vertical-dock-svg`（340×520，四个纵向 tab：概况 / DPI / 参数 / 设置）。
下面只写"能带走的东西"和"照抄会踩的坑"，逐条给数字。

## 一、它的分层（这本身就是最值得学的设计）

| 层 | 内容 | 作用 |
| --- | --- | --- |
| 0 背景 | 浅灰对角渐变 | 假壁纸，给玻璃一个可折射的底 |
| 1 底座（shelf） | 竖向圆角矩形 `110,45,120×430 r36`，白 0.55/0.25/0.45 横向渐变填充 + 白 0.9→0.3 纵向渐变描边，双 `feDropShadow` | 玻璃槽体，靠描边渐变造"上亮下暗"的受光 |
| 2 基础文字 | 四个 20px 常规字重 `#4b525d` 标签 | 常态状态 |
| 3 滑块（胶囊） | 86×86 r24，紫蓝渐变 + 白→#9eb1f2 描边 + **顶部一条白色圆头高光线**（`M143 63.5 L197 63.5`） | 激活态；高光线就是 Liquid Glass 的镜面切边 |
| 4 透镜文字层 | 同样的四个标签，放大 1.1x、颜色换成 `#22379b`，整层被 `clipPath` 裁在滑块的圆角矩形内 | **假折射**：滑块走到哪，哪一段文字就"被放大、被染色" |
| 5 交互热区 | 四个透明 86×86 矩形 + 顶层 pointer 事件 | 命中 |

关键点：**透镜层与滑块共用同一个 transform 字符串**（`applySliderTransform` 同时写给 `#glass-slider` 和 `#clip-rect`），
所以"玻璃"和"被放大的文字"永远严丝合缝——这是整套折射幻觉成立的前提。

## 二、六个可以直接带走的技术

1. **透镜剪裁（Lens Clip）**：两份文字，上面那份放大 1.1x + 换强调色，裁进指示器的圆角矩形里；
   指示器移动时剪裁窗口同步移动。不需要任何 shader 就得到"局部放大 + 变色"的折射观感。
   染色是第二个收益：激活项自动变成强调色，**不需要另写选中态样式**。
2. **体积守恒形变**：`stretchY = min(1 + v·0.012, 1.10)`、`compressX = 1/√stretchY`。
   Y 拉长时 X 收窄，面积近似不变 → 读起来像液体而不是"被拉长的图片"。
   上限 1.10 很关键，超过就是橡皮筋。
3. **指数阻尼硬边界**：`damped = allowedTravel · (1 − e^(−pull/40))`。
   拖动越界时位移渐近逼近硬边界（`MIN_HARD_Y=94` / `MAX_HARD_Y=401`），**永远不会越过**，
   也不会有"撞墙"的硬拐点。比线性阻尼（`pull·0.35`）好：后者要额外 clamp，且手感是断的。
4. **贴壁压缩**：拖到两端时把 `stretchY` 换成 `0.96`（配合 `compressX = 1/√0.96 ≈ 1.02`）——
   "液体被挤在壁上"的暗示，比只做位移停止高级得多。
5. **读渲染值续接**：`getCurrentRenderedY()` 从 `getComputedStyle().transform` 里解析矩阵拿**当前渲染位置**，
   而不是自己维护的 `currentY`。这正是原则 1 在网页里的写法：打断时以"画面现在在哪"为起点。
6. **松手分两路 + 时长随距离**：
   - 贴壁 → `cubic-bezier(0.18, 1.25, 0.35, 1.0)`（y 控制点 1.25 > 1，即过冲回弹），0.85s；
   - 普通 → `cubic-bezier(0.05, 0.7, 0.1, 1.0)`（强减速、长尾），时长 `clamp(1.0 + 距离·0.0035, 1.1, 1.8)s`。

   另外视觉配方：双 `feDropShadow`（宽软 + 紧实）叠出材质厚度；底座描边用纵向渐变；
   胶囊顶部一条圆头白线当镜面高光。

## 三、移植前必须改的四处

1. **帧率依赖（最容易忽略）**：`currentY += diff·0.08` 与 `velocity = |currentY − lastY|` 都是"每帧"量。
   120Hz 屏上：滞后时间常数从 `1/0.08 = 12.5 帧 ≈ 208ms` 掉到 `≈104ms`，速度读数直接减半 → 拉伸几乎消失。
   改成时间无关：`alpha = 1 − exp(−dt/τ)`、`v = Δy/Δt (px/s)`，
   拉伸系数按 px/s 重算（原式换算约 `stretch = clamp(1 + v·0.0002, 1, 1.10)`）。
2. **拖拽期的滞后是"重液滴"，不是"跟手"**：τ≈208ms 意味着胶囊明显拖在手指后面（最多约 1/5 秒）。
   对 86px 的小胶囊这是有意为之的液体感，**可以留**；但：
   - 内容/页面被拖动时不能这么干（原则 4 要求 1:1）；
   - 指示器类元素建议 τ ≤ 30–80ms，超过就有"脱手"感。
3. **`transform-origin` 只在"几何固定、位置全靠 translate"时才对**：这里写死 `170px 105px`，
   恰好等于胶囊自身中心（矩形固定在 `127,62,86×86`，四个位置的差别全在 `translateY`）。
   一旦改成"每个 item 一个胶囊"或改 `y` 属性，这个原点就会偏，缩放不再绕自身中心——
   越靠下的 item 偏得越多。稳妥写法：`transform-box: fill-box; transform-origin: 50% 50%`。
4. **矩阵解析的脆弱点**：`getCurrentRenderedY()` 只匹配 `matrix(...)` 六值形式；
   一旦被提升成 `matrix3d(...)`（合成层、3D 祖先、部分浏览器优化）就静默退回 `currentY`，
   打断续接随之失效。用 `new DOMMatrix(style.transform)` 解析，或把位置状态机放在 JS 里统一维护。

## 四、两个应当写明的取舍

- **时长偏长**：1.1–1.8s 的滑行对"指示器"是刻意的流体感，对"内容切换"就是迟钝。
  经验口径：指示器/胶囊 0.6–1.2s 可接受，内容入场 0.2–0.34s。
- **缺无障碍**：没有 `role="tab"` / `aria-selected`、没有方向键、点击热区写死 `x∈[110,230]`。
  造型可以只做视觉，但键盘与语义必须补。

## 五、WPF 对应写法

| 网页做法 | WPF 对应 |
| --- | --- |
| 两份文字 + `clipPath` 剪裁圆角矩形 | 一个 `Canvas` 包住放大 1.1x 的文字层，`Clip = new RectangleGeometry(roundedRect)`；与指示器共享同一组 transform |
| `translateY(offset) scale(x, y)` | `TransformGroup`（`TranslateTransform` + 非等比 `ScaleTransform`）；`RenderTransformOrigin="0.5,0.5"` —— WPF 原生绕自身中心，不会出现第三节第 3 条的问题 |
| `1 − e^(−pull/40)` 墙体阻尼 | 数学相同，直接照搬 |
| `alpha = 1 − e^(−dt/τ)` | 同上；用 `CompositionTarget.Rendering` 逐帧驱动 |
| `v = Δy/Δt`（px/s） | 同上；`stretch = clamp(1 + v·0.0002, 1, 1.10)` |
| `cubic-bezier(0.05,0.7,0.1,1.0)` | `QuarticEase{EaseOut}` 近似强减速长尾；要精确复刻就自写 `IEasingFunction`（bezier 反解） |
| `cubic-bezier(0.18,1.25,0.35,1.0)` | `BackEase{Amplitude≈0.25, EaseOut}` 近似过冲回弹 |
| 双 `feDropShadow` | 两个元素各挂一层 `DropShadowEffect`（宽软 + 紧实）叠出厚度（一个元素只能挂一个 Effect） |
| 顶部镜面高光线 | `Line` + `StrokeStartLineCap=Round`，不透明度随焦点 0.35 → 0.75 |
| 透镜层换成强调色 | 文字层用比 `Theme.Accent` 深一档的颜色（对应 `#22379b`） |

> 注意：**不要**为了复刻 bezier 而退回 `SplineDoubleKeyFrame` 关键帧动画——那正是原则 1 要避免的。
> 先用量级相近的 `EaseOut` 系缓动，不够再自写 `IEasingFunction`。

## 六、v2 引擎：巡航弹道（accel → cruise → brake）

v2 把"点击/普通移动"那条 CSS 大缓动换成了**显式速度剖面**，也就是"起步加速 → 巡航 → 临近减速 → 到点回弹"的字面实现：

```
accel      = 0.45 px/帧²                    → 60fps 下 ≈ 1620 px/s²
maxVel     = min(7.2, 4.5 + 距离·0.012) px/帧 → 约 270–432 px/s
BRAKE_ZONE = 18 px（距目标）                 → 进区后交给 CSS 软着陆
SETTLE     = 0.78s cubic-bezier(0.12, 1.25, 0.32, 1.0)
```

它买到的是**速度曲线可控**：加速度、巡航速度、刹车点各自可调，比一条 bezier 好调得多。
这是本技能的**第三条实现路线**（A 时长缓动 / B 弹簧积分器 / C 巡航弹道），
适合"长距离滑行"的指示器（dock、tab 高亮跨好几个 item），不适合内容入场（内容要 0.2–0.34s 到位）。

**它天然抗帧率的地方**：巡航期拉伸写成 `stretchY = 1 + (vel/maxVel)·0.08` ——
分子分母同为"每帧"量，帧率翻倍时比值不变 ✓。
**仍然帧率相关的**：拖拽期那条 `1 + |currentY − lastY|·0.012` 用的是绝对每帧速度 ✗，
120Hz 下拉伸几乎减半，要按 §二 A 的口径换成 px/s。

### 移植前必须补的两处（v2 新引入）

1. **松手不继承手指速度**：无论拖多远，`driveToTarget` 都从 `vel = 0` 起跑
   → 快速甩动会"先死停再重新起步"，这正是"不跟手"最典型的症状。
   修法：松手瞬间测到的速度（px/s）换算成 px/帧当 `vel` 初值；速度够大时直接跳过加速段进巡航。
   只有**点击**（从未拖动过）才允许从 0 起跑，且加速段控制在 ≤8–10 帧（130–170ms）。
2. **末段回弹被固定刹车区吃掉了**：刹车区固定 18px，而 `cubic-bezier(0.12,1.25,0.32,1.0)` 的过冲只有约 **2%**
   → 实际回弹 = 18px × 2% ≈ **0.4px**，肉眼看不出；贴壁回弹那一下（`allowedTravel` 仅 11px）≈ **0.2px**，同样不可见。
   而且**固定 18px 却给 0.78s**：末段平均速度只有约 **23 px/s**，长途滑行的最后这 18px 会明显"蠕动"。
   刹车区、刹车时长、回弹幅度三者应当一起随距离缩放。三选一：
   - 刹车区随距离缩放 `clamp(距离·0.15, 18, 60)`（60px × 2% = 1.2px，仍偏小）；
   - 过冲 bezier 提到 `cubic-bezier(0.2, 1.6, 0.4, 1.0)`（过冲 ≈10%）；
   - **推荐**：把回弹做成 JS 里的**绝对像素**过冲（+4–6px 再回落），与行程长度解耦。

### 值得保留的三个工程细节

- **JS 弹道 + CSS 软着陆的交接**：交接前最后一次 `transform` 由 JS 写（`transition: 'none'`），
  交接时**不重写坐标**、只设置最终位置并挂上 `transition` —— CSS 会从**当前渲染值**起步，衔接无缝。
  同时 JS 状态在交接瞬间直接跳到终点（`currentY = destY`）：位置由渲染值负责，状态只用于续接计算。
- **初始化直接落位**：`applySliderTransform(0, 1, 1, 'none')`，不在启动时播一段动画（避免"开机自己动一下"）。
- **删掉挂在元素上的全局 CSS transition**：v1 在 `#glass-slider, #clip-rect` 上常驻 1.2s transition，
  会与 JS 逐帧写 transform 互相打架（JS 每帧都得显式覆盖它）；v2 只在需要软着陆时逐次显式设置 ✓。
